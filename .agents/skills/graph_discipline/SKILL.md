# Graph discipline

Three sources, three jobs:
1. docs/GRAPH.md: code facts (files, uses, used_by, signals with emitters and listeners). Auto generated by python tools/gen_graph.py. Never edit by hand.
2. docs/PROJECT_MAP.md: module purposes and public contracts (methods, signals, exports, groups, input actions).
3. Memory MCP graph: intent, invariants, decisions, and couplings the scanner cannot see (node paths, scene wiring, groups, tuning assumptions).

## Before editing
1. memory search_nodes with the module name. Read its observations and relations.
2. python tools/gen_graph.py --impact <file>.
3. If the change touches a contract, list every user first, then change them all in the same task.

## After editing
1. Validate with Godot MCP, fix errors.
2. python tools/gen_graph.py
3. Update PROJECT_MAP.md only if a contract changed.
4. Memory graph update: add_observations to touched entities, create_relations for new couplings, delete_observations for stale facts.
5. python tools/check_project.py if text or assets changed.

## Memory schema
Entity names: module:player, module:heat, scene:chapter_1_shore, autoload:game_state, contract:hope_scale, decision:camera_perspective.
Entity types: module, scene, autoload, contract, decision.
Observations: one short fact each, English, no dashes. Example: "hope range is 0 to 100".
Relations in active voice: emits, listens_to, depends_on, owns, guards, scene_couples_to.
Never call read_graph. Never store secrets or paths outside the project.
